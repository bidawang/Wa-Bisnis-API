CAMPING RENTAL - LARAVEL ELOQUENT MODEL & RELATION REFERENCE
==============================================================

Database target: MySQL 8.0+
Laravel: gunakan namespace App\\Models dan sesuaikan fillable/casts dengan kebutuhan aplikasi.

DESAIN INTI
-----------
1. user -> tempat_sewa -> barang/paket
2. barang -> barang_stok + foto + tutorial
3. booking -> booking_detail -> barang/paket
4. booking -> sewa -> sewa_detail
5. tagihan menjadi pusat perhitungan nilai transaksi.
6. pembayaran selalu mengacu ke tagihan.
7. transaksi mencatat pergerakan uang pada dompet.
8. stok_mutasi menyimpan histori perubahan stok.
9. harga transaksi disimpan sebagai snapshot; perubahan harga master tidak mengubah transaksi lama.

ATURAN TOTAL
------------
Detail:
  subtotal       = jumlah * harga_satuan
  diskon_nominal = hasil diskon aktual
  total          = subtotal - diskon_nominal

Tagihan:
  subtotal        = SUM(tagihan_detail.total)
  diskon_nominal  = diskon tagihan
  total           = subtotal - diskon_nominal + biaya_tambahan
  dibayar         = SUM(pembayaran yang bukan refund) - SUM(refund)
  sisa            = total - dibayar

DISKON
------
Diskon dapat berupa:
  diskon_tipe  = nominal | persen
  diskon_nilai = angka input user
  diskon_nominal = nilai rupiah yang benar-benar diterapkan

Contoh:
  subtotal = 500000
  diskon_tipe = persen
  diskon_nilai = 10
  diskon_nominal = 50000
  biaya_tambahan = 25000
  total = 475000

Jangan menghitung ulang transaksi lama dari harga master barang/paket.
Gunakan harga_satuan dan diskon_nominal yang sudah tersimpan pada detail/tagihan.

    }
}

==============================================================
ALUR DATA UTAMA
==============================================================

1. BARANG MASUK
   BarangMasuk -> BarangMasukDetail -> update BarangStok -> catat StokMutasi(tipe=masuk)

2. BOOKING
   Booking -> BookingDetail -> cek BarangStok.jumlah_tersedia
   Jika dikonfirmasi:
      kurangi jumlah_tersedia
      tambah jumlah_dipesan
      catat StokMutasi(tipe=reservasi)

3. PEMBATALAN BOOKING
   Booking -> BookingCancel
      kurangi jumlah_dipesan
      tambah jumlah_tersedia
      catat StokMutasi(tipe=batal_reservasi)

4. BOOKING MENJADI SEWA
   Booking -> Sewa
   BookingToSewa menjadi relasi historis
   stok:
      jumlah_dipesan -= qty
      jumlah_disewa += qty
      catat StokMutasi(tipe=keluar_sewa)

5. PENGEMBALIAN
   Sewa -> SewaDetail
   untuk barang kembali baik:
      jumlah_disewa -= qty
      jumlah_tersedia += qty
      StokMutasi(tipe=kembali)
   untuk barang rusak:
      jumlah_disewa -= qty
      jumlah_rusak += qty
      StokMutasi(tipe=rusak)

6. TAGIHAN
   Tagihan -> TagihanDetail
   Tagihan menyimpan snapshot subtotal, diskon, biaya tambahan, total.

7. PEMBAYARAN
   Tagihan -> Pembayaran
   Satu tagihan boleh memiliki banyak pembayaran.
   Pembayaran -> Transaksi -> Dompet

8. PERUBAHAN HARGA
   Barang.harga / Paket.harga_paket hanya harga master.
   Transaksi lama memakai TagihanDetail.harga_satuan.
   Karena itu histori transaksi tetap aman.

==============================================================
CATATAN IMPLEMENTASI PENTING
==============================================================

- Jangan mengizinkan jumlah stok negatif.
- Operasi booking/sewa/pengembalian stok harus memakai DB::transaction().
- Saat memproses stok, gunakan lockForUpdate() pada BarangStok untuk mencegah dua transaksi mengambil stok yang sama.
- Jangan memberi Gemini akses SQL langsung. AI hanya menghasilkan intent/parameter; Laravel melakukan query dan perubahan stok.
- Harga, diskon, dan total transaksi sebaiknya dihitung oleh Laravel, bukan AI.
- Tagihan adalah sumber utama nilai transaksi; pembayaran adalah arus uang yang masuk/keluar terhadap tagihan.
- Transaksi adalah catatan arus kas pada dompet; jangan menggunakan transaksi sebagai pengganti pembayaran.
